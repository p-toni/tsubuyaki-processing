# v0.14 Cold End-to-End Test — Frozen Protocol

## Question

Does the production v0.14 boundary work on fresh unseen briefs?

```text
expanded discovery
-> visual + temporal ranking
-> adaptive compression-survival preflight
-> deployment finalist
-> full golf
-> exact verification
```

## Routes / briefs

### Recurrence — high compression-risk
Create one coherent **tidal living knot** from recurrent state: a dense soft body with internal crossing, slow orbital breathing, and a transformed projection that does not read as a stock Lorenz butterfly.

Frozen invariants:
- stateful recurrent kernel;
- one coherent body;
- transformed projection;
- visible internal crossing / volume;
- continuous slow motion;
- no textbook attractor silhouette.

### Dense sheet — control
Create an abstract **split veil / folded petal membrane** from true flattened 2D sampling: one membrane system with a legible central negative-space seam, layered translucent folds, and slow coordinated breathing; no explicit creature anatomy.

Frozen invariants:
- true 2D sheet sampling;
- one coherent membrane system;
- stable central negative-space seam;
- layered fold/material identity;
- slow coherent motion;
- no explicit anatomy.

## Search

For each route:
1. establish one viable incumbent;
2. generate 10–12 fresh challengers using current progressive route policy;
3. preserve incumbent and brief invariants;
4. render at matched representative times;
5. freeze visual/temporal ranking without inspecting code length or compactness.

Character count, compact-cause estimates and tweetability are forbidden during generation/ranking.

## Deployment promotion

After rankings are frozen:
1. preflight rank #1 by naming its defining mathematical relationships;
2. build the cheapest plausible semantic compression preserving those relationships;
3. render representative times;
4. mark compression survival pass/fail;
5. on fail, preserve the artistic winner and continue to rank #2, then lower only if necessary;
6. stop at the first passing visually worthwhile candidate.

`<=280` alone is not a pass.

## Full golf

Golf only the deployment finalist. Then require:
- complete post <=280 X-weighted chars;
- parse/runtime pass;
- finite coordinates;
- representative-time phenotype survival.

## Primary outcomes

Per route:
- artistic rank #1;
- number of preflights needed;
- deployment finalist rank;
- whether preflight predicted final golf survival;
- whether final golf retained defining phenotype.

## Failure signals

- artistic ranking changes after length information is revealed -> boundary contamination;
- preflight passes but full golf loses identity -> preflight false positive;
- preflight fails but a faithful <=280 final form exists -> preflight false negative;
- fallback selects a clearly worse/off-brief candidate -> deployment gate overrules art incorrectly.

No production policy changes during this run.
