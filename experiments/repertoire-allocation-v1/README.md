# Repertoire allocation v1 — preregistered consumed-seed pilot

## Question

Once a route has multiple explicit basin lineages and a qualified rendered phenotype map, does **preserving phenotype-niche coverage while allocating depth inside each basin** improve target-agnostic search robustness relative to ordinary lineage deepening?

This experiment tests allocation only. It does **not** retest or use the unconfirmed #72/#73 restricted trust-region mutator.

## Scientific boundary

Frozen shared mechanics:

- five fixed route strata: `recurrence`, `orbit`, `family`, `sheet`, `filament`;
- six selector-independent hard-valid independent starts per route/seed;
- each start is its own explicit basin lineage;
- exactly six mutation events per basin = **36 generated candidates per arm per route/seed**;
- exact same per-basin budget in both arms;
- exact same event-keyed RNG stream for corresponding mutation events;
- exact same generic whole-genome route mutator (`ROUTES[route]["mutate"]`);
- exact same deterministic mutation-scale schedule per basin: `1.0, 0.7, 0.55, 1.2, 0.7, 1.0`;
- invalid candidates consume budget in both arms and never become parents;
- no diagnostic score, target distance, human judgment, or route preference participates in parent selection.

The **only intervention** is the parent chosen inside the already-assigned basin budget.

### Baseline: `lineage-depth`

For a basin's next event, mutate its **most recent valid descendant**. This creates the ordinary depth-first chain implied by repeated generic exploitation.

### Candidate: `repertoire-preserving`

For the same basin's next event:

1. group all valid descendants of that basin by frozen `structural-v1` phenotype niche;
2. choose the niche that has received the fewest prior parent selections in that basin;
3. break ties by frozen niche key, then candidate id;
4. mutate the most recent valid candidate in that niche.

A newly discovered niche therefore receives future exposure instead of being immediately abandoned, but it cannot steal budget from another basin or route.

## Consumed pilot population

Use these 16 already-consumed #71 master seeds:

```text
1009, 1013, 1019, 1021,
1031, 1033, 1039, 1049,
1051, 1061, 1063, 1069,
1087, 1091, 1093, 1097
```

The first 12 were used in #72 and the final four were subsequently consumed in the #74 niche audit. No seed is fresh search-policy evidence.

Expected rectangle:

```text
16 master seeds × 5 fixed routes = 80 route×seed blocks
```

No early stopping, seed replacement, route voting, or post-hoc exclusion.

## Independent target portfolio

Neither arm sees a target during allocation.

After the shared six starts are generated, freeze eight independently generated target probes per route/seed:

- **six basin-local probes**: one per starting basin, produced by three accepted generic mutation steps from that basin's start at scale `0.8`, using target-only RNG streams;
- **two global probes**: independently seeded valid route phenotypes from target-only RNG streams.

Targets are generated before either allocation arm and are identical for both arms.

Target scoring uses the already-qualified `sparse-geometry-v1` metric from #69. This metric is an outcome measure only; it never affects parent allocation.

## Capability outcome

For every target `t`:

```text
initial_best[t] = best sparse-geometry distance among the six shared starts
final_best[p,t] = best distance among shared starts + all valid candidates generated by policy p
normalized_gain[p,t] = (initial_best[t] - final_best[p,t]) / initial_best[t]
```

Because the shared starts remain in each pool, gain cannot be negative except for numerical tolerance.

Per route×seed:

```text
portfolio_mean_gain[p] = mean over the 8 target gains
portfolio_lower_half_gain[p] = mean of the 4 smallest target gains
primary_delta = repertoire_mean_gain - lineage_depth_mean_gain
robustness_delta = repertoire_lower_half_gain - lineage_depth_lower_half_gain
```

Primary replicates for aggregate reasoning remain complete master seeds, with route effects averaged equally within each seed.

## Mechanism diagnostics

Report but do not use to override the capability result:

- final occupied phenotype niches;
- final distinct `(basin lineage, phenotype niche)` slots;
- number of children that discover a niche not previously represented in their basin;
- unique rendered phenotype count/rate;
- valid yield;
- parent-selection counts by basin and niche;
- maximum share of a route's budget assigned to one basin (must be exactly `1/6` by construction).

These diagnostics verify that the candidate actually preserves repertoire structure without changing outer/basin budgets.

## Hard invariants

Fail closed unless all hold for every route×seed block:

1. both arms start from identical six phenotype fingerprints;
2. targets/fingerprints are identical across arms because targets are generated once before the fork;
3. each arm generates exactly 36 candidates;
4. every starting basin receives exactly six mutation events in each arm;
5. corresponding arm events use the same event-keyed RNG seed and scale;
6. both arms use the same generic route mutator;
7. no target/diagnostic score enters parent selection;
8. every repertoire parent belongs to the currently scheduled basin;
9. `structural-v1` is used unchanged from merged #76;
10. all 80 route×seed blocks are present before reduction.

## Pilot decision

Classify `PILOT_PROMISING` only if all hard invariants pass **and all three** hold:

1. complete-master-seed mean `primary_delta > 0`;
2. every leave-one-route-out mean primary effect is `> 0`;
3. complete-master-seed mean `robustness_delta > 0`.

Otherwise classify `PILOT_NOT_PROMISING`.

This is an exploratory consumed-seed gate, not a significance claim. If promising, use the observed complete-master-seed variance only to size a fresh fixed-sample confirmation. If not promising, do not tune `structural-v1` bins or the same allocator against these pilot outcomes.

Route signs, niche counts, win counts, diagnostic scores, or the prior blind human review cannot override this gate.

## Failure discipline

If not promising:

- do not tune `structural-v1` on these seeds;
- do not alter the six-per-basin budget after seeing results;
- do not retrofit target-aware parent selection;
- diagnose whether the failure is allocation, phenotype preservation, or target-portfolio mismatch, then move up a level rather than mining route-specific wins.

## Boundary

Mechanical search-capability experiment only. No artistic authority, route pruning/promotion, default-policy change, fresh confirmation, or `SKILL.md` change.
