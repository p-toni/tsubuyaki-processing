# v0.6 Validation Notes

## Why this release exists

The v0.5 radial-family cold test found a semantic blind spot:

```text
aggregate family width ↑
```

could pass even when individual siblings behaved approximately like:

```text
+4%, -3%, +77%, +66%, -6%
```

The visible family bounding box got larger, but the requested meaning — “lengthen this repeated family coherently” — did not hold across instances.

## Exact checker regression

`check-family-math.mjs` was syntax-checked under Node and run against two five-instance pure probes using the same contract:

```text
source: math-family
field: radial
metric: max
direction: increase
min median relative change: 2%
min directional agreement: 80%
max relative MAD: 5%
```

### Coherent family

The probe produced approximately:

```text
+8%, +8%, +8%, +8%, +8%
```

Result:

```text
median relative change: ~8.0%
directional agreement: 100%
relative MAD: ~0%
PASS
```

### Incoherent / aggregate-cheat family

The same global control was wired through instance-dependent coefficients, producing mixed behavior with some shrinking siblings and two extreme growers.

Result:

```text
median relative change: ~4.0%
directional agreement: 60%
relative MAD: ~10%
min response: ~-6%
max response: ~+50%
FAIL agreement
FAIL dispersion
```

This is the intended distinction.

## Why math-space is the stronger source here

The repeated family already has a stable mathematical identity (`instance`). Reconstructing those siblings from raster connected components would be less direct and more fragile under overlap, transparency, or motion.

The pure probe evaluates the generator **before rasterization**, so the validator sees the same latent variable that actually controls the form.

Raster scope remains useful afterward to detect unintended leakage into other anatomy.

## @yuruyurau structural study

Two public examples motivated the broader math-first path.

### Recurrence + projection

One piece contains a three-state recurrent kernel equivalent to an Euler integration of:

```text
x' = 9(y-x)
y' = x(28-z)-y
z' = xy-2z
```

This is Lorenz-like but uses artistic parameters `(9,28,2)`, not Lorenz's canonical `(10,28,8/3)`.

The state is then transformed by time-, state-, and residue-dependent nonlinear projection. The visible form is therefore an emergent phenotype of **dynamics + projection**, not a literal 3D Lorenz plot and not explicit anatomy.

### Harmonic latent body + discrete family

Another piece uses one bounded harmonic latent pair and a family variable derived from `i%16`. A shared nonlinear magnitude/phase/deformation law then projects all 16 instances.

The useful abstraction is:

```text
harmonic latent body
→ scalar deformation
→ family-conditioned phase
→ shared nonlinear projection
```

## Interpretation

v0.6 does **not** attempt symbolic understanding of arbitrary golfed JavaScript.

Instead it makes the readable source structurally inspectable:

```text
pure math probe + explicit latent roles
```

This is deliberate. Parsing a 270-character one-liner after golf is the wrong place to recover semantics that were available during design.

The target workflow is:

```text
mathematical cause
→ latent semantic validation
→ raster scope / visual QA
→ golf
→ phenotype survival check
```

rather than:

```text
render first
→ infer all semantics back from pixels
```
