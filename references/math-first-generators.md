# Math-First Generators

v0.6 adds a second path for controllable complexity: **inspect and design the mathematics itself before inferring anatomy from pixels**.

This is especially important for compact #つぶやきProcessing work where creature-like forms can emerge from a few equations without a conventional body graph.

## 1. Two legitimate ways to get organism-like complexity

### Morphology-first

Use when the user explicitly wants named anatomy, attachments, or semantically editable regions:

```text
root → regions → organ families → projection
```

This remains the right path for requests such as “widen the fins but keep the tail unchanged.”

### Math-first

Use when the visual identity can emerge from a compact mathematical generator:

```text
kernel → latent coordinates → family operator → deformation → projection
```

This is often closer to the strongest tiny-code examples. The rendered result may resemble a jellyfish, starfish, larva, flower, shell, or other organism even though the source never names those parts.

Do not force a scene graph onto an equation that already contains its own morphology.

## 2. Read the generator in layers

When studying or designing a compact system, identify these roles.

### A. Kernel

What produces the underlying state or manifold?

Typical kernels:

- iterative dynamical state: `S[n+1]=F(S[n])`
- 1D harmonic/parametric curve
- flattened 2D manifold
- coupled oscillator / attractor

The kernel determines intrinsic dimensionality and long-range coherence.

### B. Latent coordinates

Derive a few shared quantities before screen projection:

```text
k,e       local / harmonic body coordinates
d         radius, magnitude, energy, distance, or field strength
c         phase / orientation
p,q       scale / deformation / projected radius
```

These are often more semantically meaningful than final `x/y` pixels.

### C. Family operator

A residue or parity expression can create many related forms from one generator:

```js
m=i%N
s=i&1
```

The important point is not merely repetition. The family id should alter a shared phase/deformation law, so siblings are generated by the same mathematics.

### D. Nonlinear deformation

High-leverage compact operations include:

- powers / fractional powers
- nested `sin/cos`
- magnitude powers
- reciprocal terms
- phase feedback such as `sin(d*d-t+m)`
- control values derived from one shared field

These can create apparent anatomy without explicit parts.

### E. Projection

The final screen coordinates often transform the latent system radically:

```text
latent state → polar/harmonic projection → point field
```

A chaotic attractor need not be drawn in its literal x/y/z axes. A nonlinear projection can turn the same state into shells, lobes, membranes, or multiple phased families.

## 3. What the @yuruyurau examples teach

Do not copy the formulas. Extract the structural ideas.

### Modified Lorenz-like piece

The published code contains a recurrent three-state core equivalent to an Euler step of:

```text
x' = 9(y-x)
y' = x(28-z)-y
z' = xy-2z
```

That is **not** the canonical Lorenz parameter set (`10,28,8/3`); it is a compact artistic variant (`9,28,2`). The state is then fed through time-, state-, and residue-dependent nonlinear radial/phase terms before projection.

Key lesson:

> the visible creature is produced by **dynamical memory + projection**, not by drawing anatomical pieces.

The residue term (`i%9`) behaves like a compact family/phase operator layered onto one chaotic trajectory.

### Harmonic 16-family piece

Another published piece uses a bounded harmonic latent body, then calls one generator with a discrete family parameter derived from `i%16`.

Structurally it behaves like:

```text
harmonic latent pair (k,e)
→ scalar magnitude/deformation d
→ nonlinear scale p
→ shared phase c + family offset m
→ harmonic screen projection
```

The 16 apparent siblings therefore come from **one latent body + 16 phase-conditioned instances**, not 16 separate organs.

Key lesson:

> a family index can be a developmental variable, not just a rendering convenience.

## 4. Generation workflow for math-first organisms

Before naming anatomy, write a short **math contract**:

```text
kernel:       recurrence / 1D / 2D / attractor
latent fields: k,e,d,...
family law:   instance expression and count, if any
deformation:  which nonlinear field creates shape differentiation
projection:   polar / harmonic / folded / direct
motion:       where time enters the system
```

Then ask:

1. Does the kernel already provide global coherence?
2. Can one family operator produce repeated morphology?
3. Can a control act on a latent role rather than arbitrary pixels?
4. Does the projection amplify a small mathematical distinction into useful visual structure?

Only introduce explicit morphology regions if the requested control cannot be expressed naturally in the generator.

## 5. Math roles are better semantic controls

Prefer controls attached to mathematical roles:

- recurrence parameter
- family count / family phase spacing
- radial extent
- axial extent
- latent magnitude scale
- deformation exponent
- cavity/repulsion field
- projection harmonic
- phase lag

This is often more robust than attaching semantics after rasterization.

Example:

```text
armLength → per-instance latent radial extent
```

is stronger than:

```text
armLength → aggregate width of all arm pixels
```

because the first states what the generator actually means.

## 6. Inspect the readable mathematics with probes

The expanded/readable source is the semantic master. For a math-aware controllable system, expose a **pure probe** that can evaluate the generator without drawing.

A probe sample should return enough structure to reason about the generator:

```js
{
  family:'arms',
  instance:3,
  x:..., y:...,
  latent:{radial:..., axial:..., phase:...}
}
```

Then the validator can perturb one control, re-run the same mathematical samples, and compare each repeated instance directly.

No image segmentation is required.

## 7. Instance-level family validation

For repeated families, evaluate the declared latent observable **per instance**.

For each instance:

```text
relative change = (variantMetric - baselineMetric) / |baselineMetric|
```

Then summarize the family using:

- median relative change
- directional agreement fraction
- MAD / dispersion
- minimum / maximum instance response

A legitimate “lengthen the family” control should usually produce coherent signs across siblings.

Example:

```text
[+9%, +7%, +9%, +8%, +8%]
```

is semantically stronger than:

```text
[+4%, -3%, +77%, +66%, -6%]
```

even if both increase the aggregate family bounding box.

## 8. Math checks and image checks are complementary

Math-space validation answers:

> Did the generator change in the intended latent way?

Raster scope validation answers:

> Did that mathematical change leak into unexpected anatomy?

Visual judgment answers:

> Is the resulting phenotype compelling?

Use all three when controllability matters. Do not replace visual QA with symbolic purity.

## 9. Dynamical systems need a different interpretation

For recurrence-driven pieces, a tiny parameter perturbation can legitimately diverge globally over time. Do not apply local-family expectations to chaotic controls.

Instead distinguish:

- **structural parameters** of the recurrence (`sigma/rho/beta`-like roles)
- **projection controls** that should not alter the underlying trajectory
- **family/residue controls** layered on the projection

When the user asks for predictable local editing, prefer controlling the projection/family layer over the chaotic kernel itself.

## 10. Compression rule

The probe and math contract are design-time artifacts. They never need to fit into the tweet.

After the mathematical behavior is validated:

1. preserve the high-leverage kernel;
2. preserve the family/deformation relationship that creates identity;
3. inline/alias controls;
4. golf the renderer;
5. verify the exact golfed phenotype visually and with morphology-survival checks where applicable.

A strong tiny program should not merely be short. It should encode a **large phenotype in a small mathematical cause**.
